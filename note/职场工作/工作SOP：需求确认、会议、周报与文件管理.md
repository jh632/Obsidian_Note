# 工作 SOP：需求确认、会议、周报与文件管理

> 来源：[分享一些工作中非常好用的SOP](https://mp.weixin.qq.com/s/nuUXFEY1mdhw2CaTfmWsHA)
> 作者：一颗青梨｜公众号：随月尝云
> 发布日期：2026-10-14
> 根据原文提炼整理，速查图与填写模板为本笔记补充。

## 核心思路

**把重复工作中的关键动作固定下来，减少遗漏、返工和查找成本。**

SOP（Standard Operating Procedure，标准作业程序）可以先从一张简短清单开始：记录一项工作在什么情况下启动、依次做什么、完成时检查什么，再根据实际使用不断修改。

![[image/工作SOP速查.svg]]

## 1. 需求确认：先对齐交付要求

接到任务时，确认以下四项，再用自己的话复述一遍。

| 确认项 | 要明确的内容 |
|---|---|
| 交付物 | 具体交付什么，包含哪些内容，以什么形式交付 |
| 截止时间 | 最晚什么时候提交 |
| 可用资源 | 已有资料、工具和可以调用的支持 |
| 协作对象 | 哪些环节需要配合，遇到问题找谁 |

**确认模板：**

> 我会在【截止时间】前交付【成果及内容范围】，使用【已有资源】；【协作事项】需要【负责人】配合。请确认我的理解是否准确。

## 2. 会议：把讨论变成明确的行动

| 阶段 | 关键动作 | 留下的结果 |
|---|---|---|
| 会前 | 写清本次会议要讨论和决定的事项 | 议程 |
| 会中 | 提炼结论，记录待办并确定负责人、截止时间 | 决定与行动项 |
| 会后 | 整理并及时发送纪要 | 各方可查阅的执行依据 |

原文建议在会后 **10 分钟内**发出纪要。检验会议效果时，重点看参会者是否清楚自己接下来要做什么。

**会议纪要模板：**

```markdown
会议主题：
会议时间：

主要结论：
- ……

| 待办事项 | 负责人 | 截止时间 |
|---|---|---|
| …… | …… | …… |
```

## 3. 周报：让成果、计划和支持需求可查

| 栏目 | 写清什么 |
|---|---|
| 本周完成 | 交付了什么结果，有哪些数据或记录支持 |
| 下周计划 | 准备交付什么，优先级如何 |
| 需要支持 | 需要谁在什么时间前提供什么帮助 |

持续保留这些记录，可以为后续复盘、成果梳理和职业发展提供素材。

**周报模板：**

```markdown
### 本周完成
- 【交付结果】；【数据或验证记录】。

### 下周计划
- 【优先级】完成【目标或交付物】。

### 需要支持
- 请【负责人】于【时间】前提供【具体支持】。
```

## 4. 文件管理：让文件和版本容易找到

原文给出的命名规则是：**日期_项目_版本_姓名**。例如：

```text
20261106_项目A周报_v1.0_张三.md
```

| 环节 | 操作 |
|---|---|
| 保存 | 统一命名，文件放到对应项目目录 |
| 修改 | 同步更新版本号，使文件名能够区分版本 |
| 归档 | 定期整理旧文件；原文建议目录层级控制在三级以内 |
| 交付 | 核对文件名、版本以及实际附上的文件 |

管理效果可以用一个具体问题检查：隔一段时间后，能否快速定位到需要的文件和版本？

## 从一项工作开始

选择一项经常出错、耗时或让自己反复纠结的工作，写下最容易遗漏的步骤。实际用几次，再删减无用步骤、补上遗漏项，逐步形成自己的清单。
