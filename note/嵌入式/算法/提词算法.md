# 提词算法

这类"跟随语音"的功能，本质上是**流式语音识别（ASR）+ 识别文本与稿子的实时对齐**。

## 整体流程

```
麦克风 → 流式 ASR（持续输出 partial 结果）→ 文本归一化 → 与稿子对齐、更新游标 → UI 高亮/滚动
```

Textream 的 Word Tracking 模式用的是 macOS 系统自带的语音识别，逐词高亮你念到的位置。根据 README，识别可能在设备本地完成，也可能把麦克风音频发给 Apple 处理，取决于机型、语言和系统可用性。这一点和另一个开源项目 Autocue 类似，它用 Vosk 或 Sherpa-ONNX 做流式识别，每 100ms 采一块音频，实时输出 partial 结果，不等整句说完。

## 核心：对齐算法

**1. 流式识别与 partial 结果**<br>
partial 结果会不断被修正，比如"今天天"后来变成"今天天气"。所以通常不能"识别出什么就直接信什么"，而是用最近 N 个词做滑动窗口匹配，或只提交稳定的前缀。

**2. 文本归一化**<br>
双方都要做标点去除、大小写统一、数字读法统一（"2026"和"二零二六"）。中文没有空格，一般按字或词切分。ASR 常出现同音字错误，所以很多实现会转拼音再比较，或者用拼音相似度做模糊匹配。

**3. 游标 + 局部窗口模糊匹配**<br>
稿子里维护一个"当前位置"游标，只在游标附近搜索，比如向前 30 个词、向后少量几个词。拿最近识别出的几个词，与窗口内的稿子片段比相似度，常用编辑距离、LCS 或 Needleman-Wunsch 之类的序列对齐。得分最高且超过阈值，就把游标推进到匹配末尾。

```python
def update(cursor, recognized_tail, script_tokens, ahead=30, back=3):
    best_pos, best_score = cursor, 0
    for start in range(max(0, cursor - back), min(len(script_tokens), cursor + ahead)):
        seg = script_tokens[start:start + len(recognized_tail)]
        score = similarity(recognized_tail, seg)   # 编辑距离/拼音相似度归一化
        score -= penalty(abs(start - cursor))       # 越远惩罚越大，偏向"顺着读"
        if score > best_score:
            best_pos, best_score = start + len(seg), score
    return best_pos if best_score > THRESH else cursor
```

**4. 鲁棒性处理**，也是体验好坏的分水岭：

- **漏读/跳读**：允许对齐时有间隙（gap），游标可以向前跳几个词。
- **即兴发挥**：匹配分数低时游标保持不动，不要乱跳。
- **重读/回退**：默认游标单调向前，只有连续多个词强匹配到靠前位置才允许回退。Autocue 就支持检测回退和向前跳转。
- **防抖**：用迟滞或最小连续匹配数，避免 ASR 抖动导致高亮来回闪。
- **滚动平滑**：游标是离散的，滚动动画要做插值，别让文字一跳一跳。

## 另外两种模式

- **Voice-Activated（语音触发滚动）**：这不需要识别内容，只做 VAD（语音活动检测，如能量阈值或 WebRTC VAD），说话时按固定速度滚，停了就暂停。
- **Classic**：匀速滚动。

## 相关思路

这个问题和音乐里的 **score following**（乐谱跟随，在线 DTW）、语音里的 **forced alignment**、关键词检测很像。如果追求更高精度，还可以直接用 CTC/Whisper 的词级时间戳做对齐，但延迟和算力成本会更高。
