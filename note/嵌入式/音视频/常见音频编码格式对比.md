# 常见音频编码格式对比

音频编码决定数字音频如何表示，以及是否通过压缩减少数据量。选择格式时，除了关注音质，还要考虑文件或传输带宽、编解码延迟、设备资源和目标平台支持。

## 先区分编码与容器

**编码（codec**规定音频采样如何压缩和还原，例如 PCM、AAC、Opus、FLAC。**容器（container**负责把音频数据、元数据以及可能存在的视频轨道组织到一个文件中，例如 WAV、MP4、Ogg、Matroska。

常见扩展名不能总是直接说明内部编码：WAV 常保存 PCM，MP4/M4A 常保存 AAC 或 ALAC，Ogg 可承载 Vorbis、Opus 或 FLAC。实际使用时应同时确认容器和音频编码。

```mermaid
flowchart LR
    M[麦克风或音源] --> P[PCM 采样数据]
    P --> E[编码器]
    E --> B[压缩或未压缩的音频码流]
    B --> C[容器或传输协议]
    C --> D[解码器]
    D --> R[PCM 数据]
    R --> O[扬声器或后续音频处理]
```

## 第一章：常见编码格式对比


| 格式/编码 | 码率 | 压缩比 | 类型 |
|---|---:|---:|---|
| PCM | 1411 kbps | 1:1 | 无压缩 |
| WAV | 1411 kbps | 1:1 | 通常无压缩 |
| FLAC | 700～1000 kbps | 1.4～2:1 | 无损 |
| ALAC | 700～1000 kbps | 1.4～2:1 | 无损 |
| MP3 | 128 kbps | 11:1 | 有损 |
| AAC | 128 kbps | 11:1 | 有损 |
| Opus | 32 kbps | 44:1 | 有损 |
| Opus | 64 kbps | 22:1 | 有损 |
| ADPCM | 32～64 kbps | 22～44:1 | 有损 |
| G.711 | 64 kbps | 22:1 | 有损 |

| 格式           | 压缩类型   | 主要特点                           | 常见用途                 | 主要取舍                     |
| ------------ | ------ | ------------------------------ | -------------------- | ------------------------ |
| PCM / LPCM   | 不压缩    | 直接表示采样值，易于读取和处理                | 录音母带、音频 DSP、设备内部音频链路 | 数据量大，传输和存储带宽要求高          |
| MP3          | 有损     | 历史悠久，播放器和软件支持广                 | 音乐文件、旧设备兼容           | 有损压缩；相同目标音质下通常有更新的压缩方案可选 |
| AAC          | 有损     | 有多种 profile，常见 AAC-LC、HE-AAC   | 手机、网页音频、视频伴音         | 需要确认设备支持的 profile 与封装方式  |
| Opus         | 有损     | 面向交互式音频，兼顾语音和音乐，支持低延迟          | 网络通话、语音流、实时传输        | 目标平台和硬件是否有解码支持需要确认       |
| Vorbis       | 有损     | 通用音频编码，常与 Ogg 容器配合             | 游戏资源、网络音频、既有 Ogg 内容  | 在新设备和硬件音频模块中的原生支持较少见     |
| FLAC         | 无损压缩   | 解码后可还原原始 PCM 采样，开放规格           | 无损音乐、长期保存、文件分发       | 文件通常大于有损格式；需要软件解码支持      |
| ALAC         | 无损压缩   | 解码后可还原原始 PCM 采样，常见于 Apple 音频生态 | Apple 音乐库、无损音频交换     | 需确认目标播放器、容器和编解码器兼容性      |
| AMR / AMR-WB | 有损语音编码 | 为语音设计，可在不同码率模式间切换              | 蜂窝语音、语音录制与传输         | 针对语音优化，不适合高保真音乐          |

**快速理解**PCM 适合处理和制作；MP3、AAC、Opus、Vorbis 通过丢弃部分听觉不敏感信息换取更小码流；FLAC、ALAC 通过可逆压缩减少文件大小；AMR 系列优先针对语音带宽进行优化。

## 第二章：逐一介绍

### 2.1 PCM / LPCM

PCM（Pulse-Code Modulation，脉冲编码调制）将每个采样点量化为数值。LPCM（Linear PCM）使用线性量化，是常见的未压缩音频表示。它不需要复杂的音频解码过程，适合 MCU 上的采样、滤波、混音和特征提取。

未压缩数据率可估算为：

```text
数据率（bit/s）= 采样率（Hz）× 位深（bit）× 声道数
```

例如，16 kHz、16-bit、单声道语音的原始 PCM 数据率为 256 kbit/s；44.1 kHz、16-bit、双声道音频约为 1.411 Mbit/s，尚未计入容器开销。采样率为 16 kHz 不代表编码格式；它只是 PCM 或其他编码的音频参数之一。

**常见封装：**`.wav` 文件常以 WAV 容器保存 PCM 数据。WAV 是容器名称，不等同于 PCM 编码。

### 2.2 MP3

MP3 是 MPEG Audio Layer III，属于有损感知编码。编码器依据听觉模型降低部分音频成分的精度，从而减小数据量。它在旧播放器、车载设备和通用软件上的兼容性很好。

适合需要广泛播放支持的音乐文件。若正在处理原始采样、重视后续编辑余量或追求逐样本无损还原，MP3 并不合适；反复对有损文件重新编码还会累积损失。

**常见封装：**`.mp3` 通常将 MP3 音频帧与 ID3 标签一起存储。

### 2.3 AAC

AAC（Advanced Audio Coding）是 MPEG 音频编码标准，提供多种编码对象类型和 profile。日常最常见的是 AAC-LC；HE-AAC 通过频带复制等工具面向较低码率场景。

AAC 常用于手机音频、网页播放和视频伴音。在相同码率下，编码器、profile、音源和设置都会影响最终听感，因此不能只凭扩展名或码率断定质量。设备集成时应确认具体支持的 AAC profile 以及容器，例如 MP4/M4A。

### 2.4 Opus

Opus 是面向交互式音频的有损编码，覆盖语音和音乐场景。它结合 SILK 语音编码层与 CELT 变换编码层，可根据输入和工作模式调整编码策略，并支持较短帧以降低算法延迟。

它适合语音通话、实时流和网络音频。端到端延迟还受到帧长、缓冲、网络抖动处理和播放设备影响，不能只看编码器本身。嵌入式项目应评估具体实现的 Flash、RAM、运算量，以及硬件解码器是否支持 Opus。

**常见封装：**文件中常见 Ogg Opus；实时网络场景也可通过 RTP 等协议承载。

### 2.5 Vorbis

Vorbis 是 Xiph.Org 定义的通用有损音频编码，可用于从低码率到较高质量的音频。它常与 Ogg 容器组合，因此文件常见 `.ogg` 扩展名。

读取 `.ogg` 时应确认其中实际承载的编码；Ogg 本身是容器，不是 Vorbis 的另一种叫法。新项目若需要实时语音，通常还应比较 Opus 的延迟与目标平台支持情况。

### 2.6 FLAC

FLAC（Free Lossless Audio Codec）通过预测、冗余消除和残差编码压缩 PCM。解码后可以逐样本还原编码前的音频，因此适合无损音乐存储、归档和分发。

FLAC 的压缩率取决于音源内容，通常无法像有损编码那样显著缩小文件。编码或解码仍需要处理开销；在 MCU 上使用前应检查所选实现的内存、处理时间和封装支持。

**常见形式：**`.flac` 可直接保存 FLAC 流；FLAC 也可以封装在 Ogg 或其他容器中。

### 2.7 ALAC

ALAC（Apple Lossless Audio Codec）是 Apple 的无损音频编码。与 FLAC 一样，它通过可逆压缩保存采样信息，解码后可还原原始 PCM。

它常见于 Apple 音频资料与设备工作流。跨平台交换时，应检查播放器和工具链是否支持 ALAC，以及目标容器是否匹配；如果需要广泛的无损文件交换，可同时评估 FLAC 的目标端支持。

**常见封装：**ALAC 常见于 MP4/M4A 容器中，`.m4a` 本身不能区分内部是 ALAC 还是 AAC。

### 2.8 AMR / AMR-WB

AMR（Adaptive Multi-Rate）和 AMR-WB（Adaptive Multi-Rate Wideband）是面向语音的多码率编码。编码器可依据传输条件选择不同码率模式，以在带宽占用和语音质量之间调整。

AMR-NB 面向窄带语音，常见采样率为 8 kHz；AMR-WB 使用 16 kHz 采样率，提供更宽的语音带宽。它们常出现在蜂窝语音和语音业务中，不适合以保留音乐细节为目标的录音存档。

**嵌入式提示：**如果产品要接入运营商语音链路或兼容已有语音文件格式，AMR 可能适用；如果是通用实时音频应用，则应根据网络协议和终端支持情况评估 Opus 等方案。

## 工程选型提示

- MCU 需要实时处理采样数据时，优先在 PCM 链路上完成采集、滤波和特征提取，再决定是否压缩存储或发送。
- 需要跨设备播放且文件体积较小时，比较 AAC 与 MP3 的目标平台兼容性；实时双向语音则关注 Opus、AMR 与通信协议的匹配。
- 需要保留原始采样信息时，选择 PCM、FLAC 或 ALAC；交付给用户播放时，再根据播放器生态选择容器和编码。
- 评估嵌入式编解码器时，同时测量编码/解码 CPU 占用、峰值 RAM、Flash、帧长、缓冲延迟和传输码率。
- 转换编码格式不会恢复有损压缩时已丢失的信息；从 MP3 转成 FLAC 只会得到更大的文件，不会变成无损音源。
