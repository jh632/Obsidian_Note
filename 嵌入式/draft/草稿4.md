## 底层 CO5300 驱动没有 TE 实现

`esp_lcd_co5300_spi.c` 中的 `co5300_panel_t` 结构体：

```c
typedef struct {
    esp_lcd_panel_t base;
    esp_lcd_panel_io_handle_t io;
    int reset_gpio_num;
    int x_gap;
    int y_gap;
    uint8_t fb_bits_per_pixel;
    uint8_t madctl_val;
    uint8_t colmod_val;
    const co5300_lcd_init_cmd_t *init_cmds;
    uint16_t init_cmds_size;
    struct {
        unsigned int use_qspi_interface: 1;
        unsigned int reset_level: 1;
    } flags;
} co5300_panel_t;
```

- **没有** `te_gpio_num` 字段
- **没有** TE 中断处理
- **没有** TE 等待逻辑
- `draw_bitmap` 直接 `tx_param` + `tx_color`，不等待任何信号

ESP-IDF 的 `esp_lcd_panel_ops.h` 也没有任何 TE 相关的 API（`wait_te`, `set_te_pin` 等都不存在）。

官方的 ESP LCD 框架和 CO5300 驱动 **没有实现 TE 引脚消费端**。它只是往 CO5300 发了 `0x35` 让 LCD 芯片在 TE 引脚上输出信号，但 ESP32-S3 这头 **没人读这个信号**。

要加 TE 支持，只能在 **封装层**（`dev_co5300.c`）或 **上层 LVGL flush callback** 里自己实现 GPIO 中断等待。底层驱动不动。
