## 1. 继承：C 的嵌套 struct 变成语法

### 1.1 回顾：C 里的"继承"长什么样

LVGL 类型树：`lv_button_t` 首成员就是 `lv_obj_t` → button "is-a" object。
C 里继承 = **手工嵌套 struct + 手工访问基类字段**，is-a 关系靠纪律维持；C++ 把这条纪律变成语法。

### 1.2 语法

```cpp
class Sensor {                // 基类：公共部分
public:
    explicit Sensor(uint8_t addr);
    esp_err_t read();
protected:
    uint8_t addr_;            // ★ protected：子类能用，外部不能
};

class GH3220 : public Sensor {    // ★ 继承语法：类名 : public 基类名
public:
    explicit GH3220(uint8_t addr);
    float read_temp();            // 自己的新能力
};
```

- `: public Sensor` = 继承。`public` 是继承方式，工程里 99% 用 public——含义是 **is-a**（GH3220 是一个 Sensor）
- 继承 = **复用基类的成员函数 + 加自己的新成员**，不是复制代码

### 1.3 protected：权限表补完

| 权限 | 类自己 | 子类 | 外部 |
|---|---|---|---|
| private | ✅ | ❌ | ❌ |
| protected | ✅ | ✅ | ❌ |
| public | ✅ | ✅ | ✅ |

基类里"给子类用的工具"（如 `addr_`）放 protected；对外接口放 public；内部细节放 private。

### 1.4 构造/析构顺序（编译器保证）

- 构造：**先基类后派生**（基类是地基）
- 析构：**先派生后基类**（先拆自己的，再还地基）

基类没有默认构造时，派生类必须在初始化列表里显式调用：

```cpp
GH3220::GH3220(uint8_t addr) : Sensor(addr) {}   // 先构造 Sensor 部分
```

### 1.5 内存布局：和 C 完全一样

GH3220 对象 = 完整 Sensor 子对象（开头）+ 自己的成员。C 的嵌套 struct 知识全部平移，没有新内存模型。

## 2. 虚析构：为什么基类析构要加 virtual

### 2.1 出事的场景

堆上 + 基类指针管理派生类对象（第 3 章多态的引子）：

```cpp
Sensor *s = new GH3220(0x34);
delete s;    // 危险！
```

析构函数默认**不是虚函数** → `delete` 只看指针的**静态类型** `Sensor` → 只调 `~Sensor()`。
GH3220 析构里该干的活（关硬件、释放 buffer）全部没执行 → **资源泄漏**。

### 2.2 解决：基类析构加 virtual

```cpp
class Sensor {
public:
    virtual ~Sensor() {}   // ★ 关键一行
};
```

- delete 时走**虚表**，运行期找到真实类型 GH3220 → 先 `~GH3220()` 再 `~Sensor()`（顺序又对了）
- 派生类析构自动是 virtual，不用每个都写

### 2.3 什么时候必须加 / 不用加

| 场景 | 基类析构 |
|---|---|
| 会出现"基类指针指向派生类对象"（工厂函数返回 `Sensor*`、容器存基类指针） | **必须 virtual** |
| 对象全在栈上（嵌入式默认） | 可以不加——栈对象离开作用域，编译器**静态调用**正确析构，不需要虚表 |

经验：设计"基类"时（注定要被继承、被多态使用）直接加 virtual；只做组合（has-a）的类不加。

### 2.4 成本（嵌入式注意）

有虚函数的类：每个对象多一个 **vptr（4 字节，一般在对象开头）**，每个类一张虚表（占 FLASH）。
ESP-IDF 里异常、RTTI 默认关闭，虚表是唯一的多态开销 → **按需加，不盲加**。

三/五法则引子：有虚析构的类，拷贝也要处理（`= delete` 禁掉，或自己写深拷贝），不能默认浅拷贝。

## 3. 语法映射总表

| C（你的写法） | C++ | 约束 |
|---|---|---|
| `struct GH3220 { Sensor base; ... }` + 手工访问 base 字段 | `class GH3220 : public Sensor` | 编译器保证 is-a |
| 注释"子类才能动这些" | `protected:` | 编译器强制 |
| 手工保证"先初始化基类" | 构造函数顺序 | 编译器保证 |
| 基类指针 delete 派生类对象（漏析构） | `virtual ~Sensor()` | 运行期查真实类型 |

---

## 4. 嵌入式实战要点

1. **组合优先于继承**：Device 组合类（has-a）继续用；继承用在"真的是同一族"（is-a）。GH3220/MPU6050 都是传感器 → 可以继承 Sensor；Device 里装多个传感器 → 组合
2. **别为"未来可能"提前继承**：只有一个传感器型号时，直接写 GH3220 类就行（YAGNI，和 GpioPin 删死配置一个思路）
3. **构造不碰硬件的约定在继承下不变**：派生类构造函数只存参数（先调基类构造），init() 才碰硬件——派生类的 init() 可以先调基类的 init() 再初始化自己的部分

---

## 5. 一句话总结

**继承 = C 嵌套 struct 的语法化 + 访问控制；虚析构 = 让"基类指针 delete 派生类对象"时，析构链按 派生→基类 完整执行的那一个 virtual。**
