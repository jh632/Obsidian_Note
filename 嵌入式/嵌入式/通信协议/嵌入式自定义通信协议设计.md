# 嵌入式自定义通信协议设计

> 来源：[简易嵌入式自定义协议设计思路！](https://mp.weixin.qq.com/s/pSLJ0kK9XYvD7xgEOz0QZw)
> 作者：ZhengNL（嵌入式大杂烩）
> 发布日期：2026-01-08

## 概述

文章以板间通信为场景，介绍一种由包头、ITLV 数据和 CRC 组成的轻量协议，并说明完整帧解析、逐字节流式解析、C 接口设计及后续扩展方向。示例适合短距离、低误码率的嵌入式通信；高可靠性、大数据量、多设备组网或安全敏感场景需要增加相应机制。

## 设计原则

- **统一字节序**：跨平台数据格式应明确字节序，文章示例采用小端序。
- **使用固定宽度类型**：使用 `uint8_t`、`uint16_t` 等类型表达协议字段，避免使用宽度依赖编译器的 `enum` 作为线上字段。
- **采用静态缓冲区**：嵌入式协议解析可使用固定容量缓冲区，减少动态内存管理。
- **支持流式输入**：串口等接口会分批交付数据，解析器需要保留状态并处理分段帧和连续多帧。
- **统一错误码**：通过错误码区分包头、长度、CRC、缓冲区等问题。

## ITLV 字段

| 字段 | 含义 | 常见长度 | 作用 |
|---|---|---:|---|
| I | ID / Index | 1 至 2 字节 | 标识数据类别 |
| T | Type | 1 字节 | 标识数据类型，如整数、字符串或字节数组 |
| L | Length | 1 至 4 字节 | 表示 Value 的长度 |
| V | Value | N 字节 | 携带业务数据 |

字段宽度应根据数据类别数量和单条数据最大长度确定。TCP 提供可靠、有序的字节流，但不保留应用消息边界；应用层仍需使用 `Length` 等规则划分消息。串口等板间链路通常还需要明确帧边界和错误检测方式。

## 示例帧格式

| 字段 | 长度 | 内容 |
|---|---:|---|
| `Head` | 2 字节 | 固定为 `0x55 0xAA` |
| `ID` | 1 字节 | 协议数据标识符 |
| `Type` | 1 字节 | 数据类型 |
| `Length` | 1 字节 | `Payload` 长度，最大 255 字节 |
| `Value/Payload` | 0 至 255 字节 | 业务数据 |
| `CRC16` | 2 字节 | CRC16-X25，按小端序传输 |

CRC 覆盖从 `Head` 到 `Payload` 末尾的全部字节，不包含 CRC 字段本身。固定字段共 7 字节，因此空负载帧为 7 字节，最大帧长为 262 字节。

## 两种解析方式

| 方式 | 输入 | 状态 | 适用来源 | 特点 |
|---|---|---|---|---|
| 一次性解析 | 完整帧 | 无状态 | UDP 数据报、文件读取 | 接口简单，调用方需要确认数据完整 |
| 流式解析 | 逐字节输入 | 状态机 | 串口、TCP 字节流 | 内部累积数据，可处理一帧分多次到达及多帧连续到达 |

流式解析状态依次接收包头、ID、Type、Length、Payload 和 CRC。文章示例在遇到无效数据时回到 `IDLE`，并指出解析器没有超时机制；工程实现可根据通信时序增加超时重置，避免不完整帧长期占用解析状态。

## C 数据结构与接口

文章使用固定宽度字段和固定容量缓冲区描述协议数据，并提供以下接口：

| 接口 | 用途 |
|---|---|
| `protocol_pack` | 将协议数据组装为帧 |
| `protocol_unpack` | 解析已完整接收的帧 |
| `protocol_parser_init` | 初始化流式解析器 |
| `protocol_parser_reset` | 重置解析器状态 |
| `protocol_parse_byte` | 向解析器输入一个字节 |
| `protocol_parser_get_frame` | 取出已经解析完成的帧 |

示例业务数据包括 LED 控制命令和日期时间结构体，并展示了打包、解包及逐字节解析过程。

### 跨平台编码注意事项

结构体打包属性只影响字段之间的填充，不会统一多字节字段的字节序。文章示例将业务结构体内存直接复制到 `Payload`；跨平台通信时，应按协议约定逐字段编码与解码。CRC 用于检测传输错误，不提供重传、身份认证或防篡改能力。

## 容量限制与扩展

| 字段 | 示例宽度 | 当前上限或限制 | 扩展方向 |
|---|---:|---|---|
| `ID` | 1 字节 | 256 个标识值 | 扩展为 2 字节 |
| `Length` | 1 字节 | 单帧负载最多 255 字节 | 扩展为 2 字节，或增加分包机制 |
| `Type` | 1 字节 | 示例中只作标记，未强制校验 | 用于类型校验或自动转换 |

分包传输需要包序号；多板通信可增加目标地址。若要提高链路可靠性，应按应用需求设计确认、重传和超时策略。流式解析器也应明确错误帧后的重新同步规则。

## 适用范围

- 适合短距离、低误码率的嵌入式板间通信，例如串口、SPI、I2C。
- 不适合直接承担高可靠性、大数据传输、多设备组网或安全敏感通信。
- 选择帧字段时，应根据最大负载、节点数量、错误恢复需求和内存预算确定宽度与缓冲区容量。
