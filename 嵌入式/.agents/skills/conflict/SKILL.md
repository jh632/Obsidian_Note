# Git Conflict Resolution

当用户输入 `/conflict` 时，执行以下操作：

## 步骤

1. 检查冲突文件 (`git status` 或 `git diff --name-only --diff-filter=U`)
2. 显示每个冲突文件的内容
3. 分析冲突并提供解决方案

## 冲突文件格式

冲突标记格式：
```
<<<<<<< HEAD
当前分支的内容
=======
要合并的分支内容
>>>>>>> branch-name
```

## 解决策略

1. **读取冲突文件**，识别所有冲突标记
2. **分析冲突原因**，与用户确认保留哪个版本
3. **编辑文件**，移除冲突标记，保留正确内容
4. **标记为已解决** (`git add <file>`)

## 常见解决方式

- **保留当前版本**：删除 `=======` 到 `>>>>>>>` 的部分
- **保留合并版本**：删除 `<<<<<<< HEAD` 到 `=======` 的部分
- **手动合并**：保留两边的修改，手动整合

## 注意事项

- 解决冲突后提醒用户执行 `git commit` 完成合并
- 如果冲突复杂，建议用户手动检查
