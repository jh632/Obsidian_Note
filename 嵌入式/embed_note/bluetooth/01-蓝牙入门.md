# 蓝牙入门

## 蓝牙是什么

蓝牙（Bluetooth）是一种**短距离无线通信技术**，工作在 **2.4 GHz ISM 频段**（2400–2483.5 MHz），典型通信距离 10m–100m。

名字来源于 10 世纪丹麦国王 Harald Bluetooth，意为"统一不同设备"——正如他统一了丹麦各部落。

### 两代蓝牙

| 特性 | 经典蓝牙 (BR/EDR) | 低功耗蓝牙 (BLE) |
|---|---|---|
| 全称 | Basic Rate / Enhanced Data Rate | Bluetooth Low Energy |
| 首次出现 | 蓝牙 1.0 (1999) | 蓝牙 4.0 (2010) |
| 典型用途 | 音频传输、文件传输、串口透传 | 传感器数据、IoT、可穿戴设备 |
| 功耗 | 较高（持续连接） | 极低（纽扣电池可工作数月） |
| 数据速率 | 1–3 Mbps | 125 kbps–2 Mbps |
| 连接建立 | ~100ms | ~6ms |
| 连接数 | 7 个活动从设备 | 理论无限制（实际受资源约束） |

> **ESP32 的 BLE 芯片只支持 BLE，不支持经典蓝牙。** 学习 ESP32 蓝牙 = 学习 BLE。

## 无线电基础

### 频段与信道

BLE 工作在 2.4 GHz ISM 频段，划分为 **40 个信道**，每个信道带宽 2 MHz：

```
2400 MHz                                                    2483.5 MHz
├────┬────┬────┬────┬────┬────┬────┬────┬────┬────┬────┬────┤
│ 37 │ 0  │ 1  │ 2  │ 3  │ 4  │ 5  │ ...│ 32 │ 33 │ 34 │ 35 │ 36 │
│    │    │    │    │    │    │    │    │    │    │    │    │    │
│adv │         数据信道 (0-36)                               │adv │adv │
└────┴────┴────┴────┴────┴────┴────┴────┴────┴────┴────┴────┘
 37   0    1    2    3    4    5  ...   32   33   34   35   36
 ↑                                           ↑
 广播信道                                    广播信道 (35, 36)
```

- **3 个广播信道**（37、38、39）：用于设备发现和连接建立，故意分散在频段两端以避开 WiFi 干扰
- **37 个数据信道**（0–36）：连接建立后用于实际数据传输

### 调制方式

| 模式 | 调制 | 速率 |
|---|---|---|
| LE 1M PHY | GFSK | 1 Mbps |
| LE 2M PHY | GFSK | 2 Mbps |
| LE Coded PHY (S=2) | GFSK + FEC | 500 kbps |
| LE Coded PHY (S=8) | GFSK + FEC | 125 kbps |

S=8 模式牺牲速率换取更远的通信距离（可达数百米）。

## 通信模型

### 广播与扫描

BLE 设备有两种基本角色：

- **广播者（Advertiser）**：周期性发送广播包，宣布自己的存在
- **扫描者（Scanner）**：被动接收广播包，发现周围设备

```
Advertiser                          Scanner
    │                                 │
    │──── ADV packet ────────────────→│
    │         (信道 37)               │
    │                                 │
    │──── ADV packet ────────────────→│
    │         (信道 38)               │
    │                                 │
    │──── ADV packet ────────────────→│
    │         (信道 39)               │
    │                                 │
```

广播包每隔 **20ms–10.24s** 发送一次（由广播间隔控制），每轮在三个广播信道依次发送相同内容。

### 广播包结构

```
┌──────────────────┬────────────┬──────────┬──────────┐
│ Preamble (1B)    │ Access     │ Header   │ Payload  │ CRC (3B) │
│                  │ Address(4B)│ (2B)     │ (0-37B)  │          │
└──────────────────┴────────────┴──────────┴──────────┘
```

Payload 中包含 **AD Structure**（广播数据结构），每个 AD Structure 由：

```
┌──────────┬──────────────────────┐
│ Length(1)│ Type(1) + Data(N)    │
└──────────┴──────────────────────┘
```

常见 AD Type：

| Type | 含义 | 示例 |
|---|---|---|
| 0x01 | Flags | 设备能力标志 |
| 0x08/0x09 | 完整/短本地名称 | "MySensor" |
| 0x02/0x03 | 16-bit 服务 UUID | 心率服务 |
| 0xFF | 厂商自定义数据 | 厂家 ID + 自定义 payload |

### 连接建立

当扫描者想要与广播者建立连接时：

```
Advertiser                          Initiator
    │                                 │
    │──── ADV_IND ──────────────────→│  (可连接广播)
    │                                 │
    │←── CONNECT_IND ────────────────│  (连接请求)
    │                                 │
    │←──── 数据交互 ────────────────→│  (进入连接态)
    │         (跳频通信)              │
```

`CONNECT_IND` 包含建立连接所需的所有参数：

| 参数 | 说明 | 典型值 |
|---|---|---|
| Access Address | 连接专用地址 | 随机生成 |
| Interval | 连接间隔 | 7.5ms–4s |
| Latency | 从机跳过事件数 | 0–49 |
| Timeout | 超时断开时间 | 100ms–32s |
| Channel Map | 使用哪些数据信道 | 按需分配 |
| Hop Increment | 跳频步长 | 5–16 |

### 连接态通信

连接建立后，双方按 **连接间隔（Connection Interval）** 周期性交换数据：

```
    Central                         Peripheral
        │                               │
        │←────── Data (event 1) ───────│  T=0
        │────── Data (event 1) ───────→│
        │         (间隔)                │
        │←────── Data (event 2) ───────│  T=CI
        │────── Data (event 2) ───────→│
        │         (间隔)                │
        │←────── Data (event 3) ───────│  T=2*CI
        │────── Data (event 3) ───────→│
```

- 每个连接事件（Connection Event）双方各发一包
- 信道在每个事件间**跳频**（伪随机序列），避免持续干扰
- Peripheral 可以在 `Latency` 个事件内不响应（省电）

## 协议栈架构

### 标准 BLE 协议栈

```
┌─────────────────────────────────────┐
│          应用层 (Application)         │  ← 你写的代码
├─────────────────────────────────────┤
│     GATT (通用属性协议)               │  ← 定义服务和特征
├─────────────────────────────────────┤
│     ATT (属性协议)                   │  ← 读/写/通知属性
├─────────────────────────────────────┤
│     SMP (安全管理协议)               │  ← 配对、加密
├─────────────────────────────────────┤
│     L2CAP (逻辑链路控制)             │  ← 数据分片/复用
├─────────────────────────────────────┤
│     HCI (主机控制器接口)             │  ← Host ↔ Controller 分界线
├─────────────────────────────────────┤
│     Link Layer (链路层)              │  ← 状态机、跳频、ACK
├─────────────────────────────────────┤
│     PHY (物理层)                     │  ← 2.4 GHz 射频
└─────────────────────────────────────┘
```

> **HCI 是关键分界线**：HCI 之上是 Host（软件协议栈），HCI 之下是 Controller（硬件射频）。ESP32 NimBLE 就是一个 Host 实现，运行在 ESP32 的 BLE Controller 之上。

### 角色模型

```
┌──────────────┐          ┌──────────────┐
│    Central    │ ←──────→ │  Peripheral  │
│   (中心设备)  │  BLE连接  │  (外围设备)  │
│   手机/电脑   │          │  ESP32/传感器 │
├──────────────┤          ├──────────────┤
│ • 发起连接    │          │ • 广播自身    │
│ • 读写数据    │          │ • 提供数据    │
│ • 管理连接    │          │ • 可省电      │
└──────────────┘          └──────────────┘
```

还有第三种角色：
- **Observer**：只扫描不连接
- **Broadcaster**：只广播不接受连接

## GATT：服务与特征

GATT（Generic Attribute Profile）是 BLE 数据交换的核心模型。它将数据组织为**服务（Service）→ 特征（Characteristic）** 的层级结构：

```
GATT Server (ESP32)
├── Service: Heart Rate (0x180D)
│   ├── Characteristic: Heart Rate Measurement (0x2A37)
│   │   ├── Properties: Read, Notify
│   │   ├── Value: [0x06, 0x4A, 0x00]  ← 心率 74 bpm
│   │   └── Descriptor: CCCD (0x2902)  ← 通知开关
│   └── Characteristic: Body Sensor Location (0x2A38)
│       ├── Properties: Read
│       └── Value: [0x01]  ← 胸部
├── Service: Battery (0x180F)
│   └── Characteristic: Battery Level (0x2A19)
│       ├── Properties: Read, Notify
│       └── Value: [0x5A]  ← 90%
└── Service: Device Information (0x180A)
    ├── Characteristic: Manufacturer Name (0x2A29)
    └── Characteristic: Model Number (0x2A24)
```

### 特征值的属性

| 属性 | 方向 | 说明 |
|---|---|---|
| Read | Central → Peripheral | 中心设备读取值 |
| Write | Central → Peripheral | 中心设备写入值 |
| Write No Response | Central → Peripheral | 写入但不等 ACK |
| Notify | Peripheral → Central | 外围设备主动推送（无需确认） |
| Indicate | Peripheral → Central | 外围设备主动推送（需确认） |

### Handle 与 UUID

- **UUID（通用唯一标识符）**：标识服务或特征的类型
  - 16-bit UUID：SIG 定义的标准服务（如 0x180D = 心率）
  - 128-bit UUID：厂商自定义服务
- **Handle**：每个属性在 GATT 表中的唯一编号（0x0001–0xFFFF），用于读写操作寻址

## NimBLE 简介

NimBLE 是 Apache 基金会的开源 BLE 协议栈，ESP-IDF 集成的默认 BLE Host。

### 为什么选 NimBLE

| 对比项 | NimBLE | Bluedroid |
|---|---|---|
| 代码大小 | ~50 KB | ~150 KB |
| RAM 占用 | ~10 KB | ~30+ KB |
| 许可证 | Apache 2.0 | Apache 2.0 |
| 维护状态 | 活跃 | 维护模式 |
| ESP-IDF 默认 | 是 (v5.0+) | 可选 |

### ESP32 + NimBLE 的角色分工

```
┌─────────────────────────────────────────────┐
│                ESP32 芯片                    │
│                                             │
│  ┌─────────────┐      ┌──────────────────┐  │
│  │  NimBLE      │ ←──→ │  BLE Controller  │  │
│  │  (Host)      │ HCI  │  (硬件射频)      │  │
│  │              │      │                  │  │
│  │  协议栈逻辑  │      │  PHY + Link Layer│  │
│  │  GATT/ATT   │      │  跳频/ACK        │  │
│  └──────┬──────┘      └──────────────────┘  │
│         │                                    │
│  ┌──────┴──────┐                            │
│  │  你的应用    │                            │
│  │  (GATT 服务) │                            │
│  └─────────────┘                            │
└─────────────────────────────────────────────┘
```

NimBLE 作为 Host 层，帮你处理：
- GATT 服务/特征的定义和管理
- 广播数据的组装和发送
- 连接参数协商
- 配对和加密（SMP）
- ATT 协议的消息收发

你只需要关注**应用层**：定义服务、处理读写事件、发送通知。

## 关键术语速查

| 术语 | 全称 | 含义 |
|---|---|---|
| BLE | Bluetooth Low Energy | 低功耗蓝牙 |
| GATT | Generic Attribute Profile | 通用属性协议 |
| ATT | Attribute Protocol | 属性协议 |
| SMP | Security Manager Protocol | 安全管理协议 |
| L2CAP | Logical Link Control and Adaptation Protocol | 逻辑链路控制 |
| HCI | Host Controller Interface | 主机控制器接口 |
| GAP | Generic Access Profile | 通用访问协议（设备发现/连接） |
| CCCD | Client Characteristic Configuration Descriptor | 客户端特征配置描述符（通知开关） |
| PHY | Physical Layer | 物理层 |
| RSSI | Received Signal Strength Indication | 接收信号强度 |
| MTU | Maximum Transmission Unit | 最大传输单元 |

## 小结

| 要点 | 内容 |
|---|---|
| 蓝牙 = BLE（对 ESP32） | ESP32 只支持低功耗蓝牙 |
| 频段 | 2.4 GHz ISM，40 个信道 |
| 广播 → 连接 → 数据 | 通信的三个阶段 |
| GATT 模型 | 服务 → 特征 → 值，一切数据交换都基于此 |
| NimBLE = Host | ESP32 的 BLE 协议栈，你只需写应用层 |
| 角色 | Central（手机）↔ Peripheral（ESP32） |
