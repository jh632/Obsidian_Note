struct image_header {
    uint32_t ih_magic;
    uint32_t ih_load_addr;
    uint16_t ih_hdr_size;
    uint16_t ih_protect_tlv_size;
    uint32_t ih_img_size;
    uint32_t ih_flags;
    struct image_version ih_ver;
    uint32_t _pad1;
}; ^rOcumeh4

ih_magic（镜像魔数）

作用：固定标识码（MCUboot 中为 0x96f3b83d）。Bootloader 启动时首先读取该值，用于快速验证 Flash 该位置是否存储了合法的 MCUboot 镜像，防止把空白 Flash 或乱码数据误认为固件。 ^T3qY0BvR

ih_load_addr（加载地址）

作用：指定固件运行时的目标内存（RAM）起始地址。在无法直接在 Flash 原地执行（非 XIP 模式，如外部 SPI Flash）时，Bootloader 会根据此地址将 Flash 中的固件主体复制到 RAM 中运行；若为 Flash 原地执行（XIP），大部分mcu设为 0。 ^Al7yQn0o

ih_hdr_size（头部大小）

作用：记录 Header 自身占用的字节数（通常为 32 字节）。Bootloader 通过 Header地址 + ih_hdr_size 动态定位固件主体的起始位置。这种设计实现了前向兼容，即使未来 Header 扩展变大，也不用修改跳过 Header 的偏移计算代码。 ^lXOLKP4o

ih_img_size（固件主体大小）

作用：仅指应用二进制代码（Firmware Body）的实际字节大小（不含 Header 和 TLV）。Bootloader 在验签、升级擦写、搬移 Sector 时，依赖此字段确定需要处理的具体字节数。 ^hqSwuLU1

ih_flags（标志位）

作用：存储镜像属性的 Bit 位图。Bootloader 读取这些标志位来决定后续处理行为，例如指示固件是否经过加密（需解密后再运行）、是否需要加载到 RAM 中执行等。 ^NWYmo126

ih_ver（镜像版本号）

作用：存储 SemVer 语义化版本号（包含 Major、Minor、Revision、Build Num）。主要用于安全防回滚检查（Anti-rollback）以及在多 Slot 模式下判断哪个固件版本更新。 ^zVdtWjXZ

扇区交换（Sector Swap）的 3 个原子步骤

MCUboot 在交换 Primary 和 Secondary 槽区的第 1 个 Sector（假设 Primary 为 A，Secondary 为 X）时，并非直接覆盖，而是借助 Scratch 区域分三步完成：

步骤1将 Primary A 复制到 Scratch

步骤2:将Secondary X 复制到 Primary A

步骤3将 Scratch A 复制到 Secondary X ^HJGIIIU1

Trailer ^MA88yYrH
